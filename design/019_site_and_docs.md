## Decisions
- **Astro 7.4.0 + Starlight 0.42.6 in `website/`.**
  - **Why:**
    - the landing page and the docs share components, tokens and a header in one build;
    - the landing page is a plain Astro page, with full freedom for animation;
    - Pagefind search;
    - Node 24 is already used by the TS client.
- **URLs are kept.**
  - `site: https://malayh.github.io`, `base: /tantra`, `trailingSlash: 'always'`.
  - The landing page is at `/tantra/` (`src/pages/index.astro`).
  - Docs are at `/tantra/docs/<same path>/` (`src/content/docs/docs/**`).
  - The IA lives in the sidebar config, so files keep their paths. README, pyproject and CHANGELOG links keep working.
- **Hand-written reference with coverage tests.** Every exported symbol must have a reference entry, and a test enforces it (P4).
- **All site code is real code.**
  - Snippets come from `examples/` files through region markers, and tests run those files.
  - Every landing claim has a source ref in the claims audit (P2).
- **Brand:**
  - **Colors:** the logo gradient `#F97316`→`#E11D48`, deep `#9F1239`, on near-black, with a warm-white light theme.
  - **Fonts:** Geist Variable + Geist Mono Variable via Fontsource, self-hosted.
  - **Themes:** both on the landing page and the docs, via Starlight's `localStorage['starlight-theme']` and `<html data-theme>`.
- **Diagrams** are hand-made SVG Astro components on the shared tokens, used on both the landing page and the docs.
- **Headline:**
  - **H1:** "Agents that survive **the crash**." The last phrase cycles through *the crash · the redeploy · the dropped socket · the closed tab*.
  - **Eyebrow:** "tantra 2.0 — now speaking ACP".
  - **Sub:** "A durable actor runtime for Python agents. Every agent gets an inbox, a journal and one turn at a time. If a worker dies mid-turn, the journal survives and nothing runs twice; with PostgreSQL, another worker can take over its queue. Drop the connection and the client resumes from its cursor. Serve it to any ACP client."
    - Revised in P5 after review. The earlier "Kill a worker mid-turn and another takes over; reopen a tab and it replays from its cursor" overclaimed: takeover needs `PostgresCoordinator` and the next writable action after lease expiry, and a fresh tab replays from the start (only a reconnecting client resumes from its cursor).
  - **`<title>`:** "tantra — durable agents, any ACP client".
- **Versions:** `tantra-harness` 2.0.0 and `tantra-acp-client` 2.0.0.

## Considered & rejected
- **MkDocs + a custom `home.html` override:** the landing page would sit inside Material's chrome, on an unmaintained stack.
- **Zensical:** 0.0.71, too young.
- **mkdocstrings or other API autogen:** there are no docstrings to render. TypeDoc for the TS client was rejected for one consistent hand-written reference style.
- **Mermaid (`astro-mermaid`):**
  - it is about 122 MB and renders client-side;
  - it flashes on theme change;
  - it needs `mermaid@^11`, not the latest.
- **Moving the migration guides to `upgrading/`:** it creates redirects for no gain. The sidebar groups them instead.
- **Third-party embeds on the landing page (YouTube, fonts CDN):** they bring privacy and perf costs. Use a CSS mock and a link instead.
- **A JS animation framework (GSAP, Motion):** vanilla CSS/JS fits the budget.

## Risks
- **Landing copy overclaims:** gated by the P2 claims audit.
- **Snippets drift from the code:** examples are tested (P3), and the reference has a coverage test (P4).
- **Base path:** a missed `/tantra` prefix breaks links only after deploy. The link validator plus the old-URL check catch it at build time.
- **Theme flash on the landing page:** `ThemeInit` must run inline in `<head>` before paint.
- **`uv lock` not run** after `mkdocs-material` is removed: `uv sync --locked` then fails for developers.
- **Pages deploys only from `main`:** nothing goes live until the branch is merged, which the user does.
